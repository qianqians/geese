# WGSL 自动提取 + 声明式管线编排 + 顶点数据反射

## Summary

为 shader_framework 新增三大能力模块：

1. **WGSL 自动提取器**（`wgsl_extract.rs`）— 用 naga AST 提取结构化元数据（bindings/structs/constants/types），用文本解析提取函数体源码
2. **声明式管线编排器**（`pipeline_compiler.rs`）— 支持扁平化混合 stage 列表（vs/fs/cs 任意混合），引擎自动拆分 compute/render pass、自动创建 BindGroupLayout/BindGroup、自动匹配参数数据
3. **顶点数据自动反射** — 从 `@vertex` entry point 的输入参数（struct 或 inline）自动提取顶点属性布局，生成 `wgpu::VertexBufferLayout`，并映射到 mesh 顶点数据语义

最终用户只需在 TOML 中声明：
```toml
stage = [["shader1.cs", "shader2.vs", "shader3.cs", "shader2.fs", "shader5.cs"]]
```
引擎自动完成：参数反射 → **顶点布局推导** → BindGroup 创建 → 执行上下文拆分 → GPU 命令编排。

## 架构总览

```
TOML stage list
    ↓
pipeline_compiler.rs (新增)
    ├─ 拆分 compute / render pass 执行序列
    ├─ 为每个函数调用 wgsl_extract 获取参数元数据
    ├─ 从 @vertex entry point 反射顶点属性布局
    ├─ 自动生成 BindGroupLayout + PipelineLayout
    ├─ 自动生成 VertexBufferLayout（顶点数据匹配）
    └─ 输出 PipelineDescriptor（可直接创建 wgpu Pipeline）
    ↓
wgsl_extract.rs (新增)
    ├─ naga 解析 → bindings/structs/constants/functions/types
    ├─ naga 解析 → vertex entry point 输入参数（struct members + @location）
    ├─ 推断 StreamSemantic（position/normal/uv/tangent/joints/weights）
    └─ 文本解析 → entry point body 源码文本
    ↓
stream.rs (已有) + compose.rs (已有) + core.rs (扩展)
    └─ StreamRouter / StreamDeclaration / ShaderModule / StageChain
```

## Task 1: WGSL 提取器 — naga 元数据 + 文本 body + 顶点反射

**新文件**: `crates/shader_framework/src/wgsl_extract.rs`

### 1.1 naga 解析入口
```rust
fn parse_naga_module(source: &str) -> ShaderResult<naga::Module>
```

### 1.2 从 naga 提取结构化元数据

| 提取项 | naga 来源 | 输出类型 |
|--------|-----------|----------|
| Entry points (name/stage/workgroup_size/args) | `module.entry_points` | `Vec<EntryPointInfo>` |
| Bindings (@group/@binding + resource type) | `module.global_variables` + `types[ty].inner` | `Vec<ShaderBinding>` |
| Structs (name/fields/attributes) | `TypeInner::Struct { members }` | `Vec<StructDef>` |
| Functions (name/params/return) | `module.functions` | `Vec<FunctionDef>` |
| Constants (name/type/value) | `module.constants` + `global_expressions` | `Vec<ConstantDef>` |
| Overrides (name/id/type) | `module.overrides` | `Vec<OverrideDef>` |
| Global vars (private/workgroup) | `module.global_variables` + `space` | `Vec<GlobalVarDef>` |
| **Vertex input attributes** | **vertex entry_point.function.arguments + types** | **`Vec<VertexAttributeInfo>`** |

**naga TypeInner → WgslType 映射**：Scalar/Vector/Matrix/Array/Image/Sampler/Atomic 全覆盖。

**Resource type 判定**：
- `AddressSpace::Uniform` → `UniformBuffer`
- `AddressSpace::Storage { access }` → `StorageBuffer { read_only }`
- `AddressSpace::Handle` + `TypeInner::Image` → `Texture/StorageTexture`
- `AddressSpace::Handle` + `TypeInner::Sampler` → `Sampler`

### 1.3 顶点输入属性反射（关键新增）

从 `@vertex` entry point 的 `function.arguments` 自动提取顶点属性：

**模式 A：Struct 参数**（如 `forward_plus.wgsl`）：
```wgsl
struct VertexInput {
    @location(0) position: vec3<f32>,
    @location(1) normal: vec3<f32>,
    @location(2) uv: vec2<f32>,
    @location(3) tangent: vec4<f32>,
    @location(4) joints: vec4<u32>,
    @location(5) weights: vec4<f32>,
};
@vertex fn vs_main(input: VertexInput) -> VertexOutput { ... }
```
naga 路径：`entry_point.function.arguments[0].ty` → resolve to `TypeInner::Struct { members }` → iterate members with `.binding: Some(Binding::Location { location })` → `.ty` resolve to type.

**模式 B：Inline 参数**（如 `shadow_depth.wgsl`）：
```wgsl
@vertex fn vs_main(@location(0) in_pos: vec3f) -> @builtin(position) vec4f { ... }
```
naga 路径：`entry_point.function.arguments` 直接有 `.binding: Some(Binding::Location { location: 0 })`。

**模式 C：@builtin 参数**（如 `forward_plus_instanced.wgsl`）：
```wgsl
@vertex fn vs_main(input: VertexInput, @builtin(instance_index) iid: u32) -> VertexOutput { ... }
```
naga 路径：参数 `.binding: Some(Binding::BuiltIn(BuiltIn::InstanceIndex))` → 标记为 `per-instance` step mode。

**反射输出**：
```rust
pub struct VertexAttributeInfo {
    pub name: String,              // "position", "normal", "uv", etc.
    pub location: u32,             // @location(N)
    pub ty: WgslType,              // Vec3(F32), Vec2(F32), etc.
    pub format: wgpu::VertexFormat, // Float32x3, Float32x2, etc.
    pub offset: u64,               // byte offset in vertex struct
    pub semantic: StreamSemantic,   // inferred from name
    pub step_mode: wgpu::VertexStepMode, // Vertex or Instance
}
```

**语义推断规则**（从字段名 → `StreamSemantic`）：
| 字段名模式 | StreamSemantic |
|-----------|---------------|
| `position`, `pos` | `Position` |
| `normal`, `nrm` | `Normal` |
| `tangent`, `tan` | `Tangent` |
| `uv*`, `texcoord*` | `UV(index)` |
| `color*`, `col*` | `Color(index)` |
| `joints`, `bone_indices` | `BoneIndices` |
| `weights`, `bone_weights` | `BoneWeights` |
| 其他 | `Custom(name)` |

**与 stream.rs 集成**：提取器同时输出 `Vec<StreamDeclaration>`，可直接注册到 `StreamRouter`。

### 1.4 文本 body 提取
- `find_brace_block(source, start)` — 花括号深度扫描
- `extract_function_body(source, fn_name)` — 按函数名定位并提取 body 文本
- `strip_vertex_boilerplate(body)` — 去除 `var output`/`return output`

### 1.5 主 API
```rust
pub fn parse_wgsl_module(name: &str, source: &str) -> ShaderResult<ShaderModule>
```
组合 naga 元数据 + 文本 body + 顶点属性信息，返回完整的 `ShaderModule`。

提取到的 `VertexAttributeInfo` 存储在 `ShaderModule.vertex_attributes: Vec<VertexAttributeInfo>` 中。

## Task 3: 声明式管线编排器

**新文件**: `crates/shader_framework/src/pipeline_compiler.rs`

### 3.1 核心概念

用户声明一个 stage 列表（扁平化、任意混合 vs/fs/cs）：
```toml
stage = [["shader1.cs", "shader2.vs", "shader3.cs", "shader2.fs", "shader5.cs"]]
```

引擎自动：
1. **拆分执行序列** — 将扁平列表按执行上下文分组：
   ```
   Phase 1: [shader1.cs]           → compute dispatch
   Phase 2: [shader2.vs, shader2.fs] → render pass
   Phase 3: [shader3.cs]           → compute dispatch
   Phase 4: [shader5.cs]           → compute dispatch
   ```
   规则：连续的 vs/fs 合并为一个 render pass；每个 cs 独立为 compute dispatch。

2. **参数反射** — 对每个 shader 函数调用 `parse_wgsl_module()` 提取：
   - 所有 `@group/@binding` 声明 → 自动创建 BindGroupLayout entries
   - 所有 struct 定义 → 用于参数类型匹配
   - entry point 参数 → 用于 vertex buffer layout 或 compute builtin

3. **统一顶点数据源反射**（跨 phase 全局收集）：

   **核心原则：统一数据源 + 按需读取**
   - 所有需要顶点数据的函数（vs、cs 等）从**同一个顶点缓冲区**获取数据
   - 数据源包含所有可能的顶点属性（position/normal/uv/tangent/joints/weights）
   - 不同函数通过各自的 `@location` 声明按需读取子集

   **实现流程**：
   ```
   Step 1: 跨所有 phase 收集顶点属性需求
     forward_plus.vs → @location(0..5): position, normal, uv, tangent, joints, weights
     shadow_depth.vs → @location(0): position
     particle_sim.cs → @location(0..2): position, velocity, lifetime
     ↓
   Step 2: 计算 @location 并集 → 统一 VertexLayoutDescriptor
     union = {0: position, 1: normal, 2: uv, 3: tangent, 4: joints, 5: weights}
     stride = 80
     ↓
   Step 3: 每个函数只读取自己声明的 @location 子集
     forward_plus.vs 读取 location 0,1,2,3,4,5
     shadow_depth.vs  读取 location 0
     particle_sim.cs  读取 location 0,1,2
   ```

   **@location 统一约定**：同一 `@location(N)` 在所有函数中代表同一语义属性。
   数据源固定布局，函数只读取自己需要的属性，未使用的 location 在函数中被忽略。

   ```rust
   pub struct VertexDataMapping {
       /// The unified vertex buffer layout (union of all needs).
       pub unified_layout: VertexLayoutDescriptor,
       /// Per-function subset: which @locations each function reads.
       pub function_subsets: HashMap<String, Vec<u32>>,
       /// semantic → data source name
       pub semantic_sources: HashMap<StreamSemantic, String>,
   }
   ```

4. **BindGroup 自动合并** — 多个 shader 可能引用同一 `@group/@binding`，编排器合并去重：
   ```rust
   fn merge_bindings(shaders: &[ShaderModule]) -> Vec<ShaderBinding>
   ```

5. **输出 PipelineDescriptor** — 包含：
   ```rust
   pub struct CompiledPipeline {
       pub phases: Vec<ExecutionPhase>,
       pub merged_bindings: Vec<ShaderBinding>,
       pub bind_group_layouts: Vec<BindGroupLayoutDescriptor>,
       /// Unified vertex layout: union of all vertex attribute needs across all phases.
       /// All functions share this single data source, each reading its own @location subset.
       pub vertex_layout: Option<VertexLayoutDescriptor>,
       /// Maps function name → which @locations it reads from the unified buffer.
       pub vertex_data_mapping: Option<VertexDataMapping>,
   }

   pub enum ExecutionPhase {
       Compute {
           shader: String,
           entry_point: String,
           workgroup_size: [u32; 3],
           bindings: Vec<ShaderBinding>,
           /// @locations this compute function reads from the unified vertex buffer.
           vertex_location_subset: Vec<u32>,
       },
       Render {
           vertex_shader: String,
           fragment_shader: Option<String>,
           vertex_entry: String,
           fragment_entry: String,
           bindings: Vec<ShaderBinding>,
           /// @locations this render pass reads from the unified vertex buffer.
           vertex_location_subset: Vec<u32>,
       },
   }
   ```

### 3.4 统一顶点数据源完整流程

```
管线所有函数 (跨 phase)
    ↓
收集所有 @location 需求:
    forward_plus.vs:
      @location(0) position: vec3<f32>     (Float32x3, 12B)
      @location(1) normal: vec3<f32>       (Float32x3, 12B)
      @location(2) uv: vec2<f32>           (Float32x2, 8B)
      @location(3) tangent: vec4<f32>      (Float32x4, 16B)
      @location(4) joints: vec4<u32>       (Uint32x4, 16B)
      @location(5) weights: vec4<f32>      (Float32x4, 16B)
    shadow_depth.vs:
      @location(0) in_pos: vec3<f32>       (Float32x3, 12B)
    particle_sim.cs:
      @location(0) position: vec3<f32>     (Float32x3, 12B)
      @location(1) velocity: vec3<f32>     (Float32x3, 12B)
      @location(2) lifetime: f32           (Float32, 4B)
    ↓
Step 2: 计算 @location 并集 → 统一 VertexLayoutDescriptor:
    location 0: position  (Float32x3, offset=0)
    location 1: normal    (Float32x3, offset=12)   *也用于 particle velocity*
    location 2: uv        (Float32x2, offset=24)   *也用于 particle lifetime*
    location 3: tangent   (Float32x4, offset=32)
    location 4: joints    (Uint32x4, offset=48)
    location 5: weights   (Float32x4, offset=64)
    stride = 80
    ↓
Step 3: 每个 phase 记录自己的 @location 子集:
    forward_plus render pass → subset: [0,1,2,3,4,5]
    shadow_depth render pass → subset: [0]
    particle_sim compute     → subset: [0,1,2]
    ↓
Step 4: 创建单一 wgpu::VertexBufferLayout:
    array_stride = 80 (统一 stride，所有函数共享)
    step_mode = Vertex
    attributes = 全量 6 个 VertexAttribute
    ↓
Step 5: GPU 侧同一个顶点缓冲区 bind 给所有 phase:
    render_pass.set_vertex_buffer(0, unified_vertex_buffer);
    compute_pass.set_vertex_buffer(0, unified_vertex_buffer);  // 若 cs 需要
    每个函数只读取自己声明的 @location，其余数据被 GPU 硬件忽略
```

**@location 语义约定**：同一 @location(N) 在所有函数中语义一致。
如 location(0) 永远是 position，location(1) 永远是 normal/velocity 等。
数据源是「超集」，函数是「子集」——函数不读取的 location 不消耗 GPU 带宽。

**CS 特殊处理**：wgpu compute pass 不支持 `set_vertex_buffer()`。
对于需要顶点数据的 cs，同一个 GPU buffer 通过 bind group 作为 storage buffer 传递：
- Render pass: `render_pass.set_vertex_buffer(0, buffer)` + VertexBufferLayout
- Compute pass: 同一 buffer 作为 `@group(N) @binding(M) var<storage, read> vertices: array<Vertex>` 通过 bind group 传递
编排器自动检测 cs 的顶点数据需求，生成对应的 storage buffer binding。

**StreamDeclaration 生成**：从统一布局的每个 attribute 生成 StreamDeclaration，
注册到 StreamRouter，供 VS↔FS 插值结构体自动生成使用。

## Risks and Mitigations

| 风险 | 严重度 | 缓解措施 |
|------|--------|----------|
| naga 解析跨文件引用失败 | 高 | 管线 shader 引用 pbr_common 的类型；缓解：先注册 library 模块，用 stub 声明或分段解析 |
| Phase 拆分规则不明确 | 中 | 明确规则：连续 vs/fs → render pass，独立 cs → compute dispatch，vs 无 fs → 仅 vertex pass |
| 参数注册表设计过复杂 | 中 | 首版仅支持 name-based 查找；binding-based 查找留作后续 |
| BindingResourceType 扩展影响现有代码 | 中 | StorageTexture 仅新增，不修改现有变体 |
| body 中 var output/return output 双重声明 | 高 | 自动剥离 + 测试验证 |
| **顶点 struct 中字段顺序与 @location 顺序不一致** | 中 | 按 struct member 声明顺序计算 offset，按 @location 值赋值 shader_location |
| **inline 参数 vs struct 参数两种模式** | 中 | 提取器统一处理：inline 直接读 argument.binding，struct 读 members[].binding |
| **per-instance 属性检测** | 低 | 仅当发现 `@builtin(instance_index)` 参数时标记 has_instance_data |
| **统一数据源的 @location 语义冲突** | 高 | 两个函数对同一 @location(N) 声明不同类型 → 检测到报错，要求用户修正 |
| **stride 对齐与 padding** | 中 | 统一布局的 stride 必须覆盖所有函数的最大属性范围，offset 按 struct member 顺序累加 |
| **cs 读取顶点数据的 wgpu 限制** | 中 | wgpu compute pass 不支持 set_vertex_buffer；需通过 storage buffer 而非 vertex buffer 传递给 cs |
| **语义推断误判** | 低 | 使用严格匹配规则 + Custom fallback，测试覆盖所有已知字段名 |

## Rejected Alternatives

### 1. 纯文本解析（无 naga）
否决：naga 已作为依赖存在，可免费获得所有结构化信息，无需手写 400 行解析器。

### 2. 纯 naga 提取（含 body 反编译）
否决：naga IR 函数体是 Statement/Expression 图，还原为 WGSL 文本需 2000+ 行反编译器。

### 3. 保持按 stage 类型分组（不扁平化）
否决：用户明确要求扁平化混合列表，引擎自动拆分执行上下文。

### 4. 参数手动声明（不反射）
否决：用户明确要求通过 naga 反射自动获取参数，减少手动声明。
